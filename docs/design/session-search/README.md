# 会话全文搜索（session-search）需求设计

> 2026-11-14 立项。状态：v1 实现中。
> 现状缺口：左栏搜索框的远端检索（`search.all`）只覆盖**文件路径**与**会话标题**——
> 用户无法找到「聊过 X」的那次对话内容。历史会话累计上百个后，这是每日都会撞上的检索缺口。

## 1. 目标与非目标

**目标**：在左栏搜索框输入关键字时，除既有的「会话（标题）/ 工作区文件」两组结果外，
新增**「对话内容」**组——扫描会话事件日志（每会话一个 `.jsonl`），命中即返回
「会话标题 + 命中片段（高亮）+ 命中行数」，点击打开该会话。

**非目标（v1 明确不做）**：
- 不做正则 / 模糊 / 分词匹配——v1 是**大小写不敏感的子串匹配**（够用、可预期、零依赖）；
- 跟随 `search.all` 既有语义：跨项目搜**全量**会话（与标题组同源）；
- 不做事件时间范围 / 类型过滤——命中片段自带类型标注，过滤留给后续版本；
- 不做实时索引——直接线性扫描 `.jsonl`（本机 134 会话实测 list 全扫 47.5ms，
  内容扫描量级更大但受扫描上限约束，见 §3）。

## 2. 用户体验

- 触发：搜索框输入 ≥2 个字符（去首尾空格），防抖后随既有 `search.all` 一起返回
  （不新增请求——内容命中并入同一条 RPC 的返回体）。
- 展示：搜索结果新增第三组「对话内容」，行 = 会话标题（高亮）+ 命中片段（服务端按 ±30 字符
  截好，前端完整高亮渲染）+ 命中行数徽标（>1 时显示「N 处」）。
  组内排序：命中行数多者优先（id 兜底），与 service 返回口径一致。
- 点击 / Enter：打开该会话（与「会话」组一致——跳到会话，流视图定位留给后续版本）。
- 空态：无内容命中时该组不渲染（不影响既有两组）。

## 3. 服务端契约（`search.all` 增量）

请求不变：`{ query, limit? }`。返回体新增 `messages` 数组（既有 `files` / `chats` 不动，
纯增量，旧客户端不受影响）：

```jsonc
{
  "files": [/* 既有 */],
  "chats": [/* 既有 */],
  "messages": [
    {
      "sessionId": "s1",
      "label": "会话标题",
      "updatedAt": "2026-11-14T10:00:00.000Z",
      "matchCount": 7,
      "snippet": "……命中片段（±30 字符，含省略号）……"
    ]
  ],
  "messagesTruncated": true
}
```

扫描上限（防大库拖死一次搜索）：
| 项 | 上限 |
| --- | --- |
| 查询词长度 | 2–64 字符（越界返回判别失败） |
| 扫描会话数 | 200（主目录 + archive/ 合计，按 mtime 新者先扫） |
| 每会话命中行数计入 | 50（超过即停止该文件） |
| 每会话保留片段 | 3 条 |
| 返回结果条数 | ≤ limit（缺省 8，上限 20） |
| 超限行为 | `truncated: true`（UI 首条 hint 标注「结果已截断」） |

匹配口径：事件读取统一走 `Agent.eventsOf`（在跑会话取内存事实源、其余取存档、纯读
不广播），对每条事件的**可读文本**做小写化子串匹配。可读文本按类型提取：`user` / `assistant` → `payload.content`；
`tool_call` → `payload.name`；`tool_result` → `payload.text`；其余类型 →
`JSON.stringify(payload)`（截 200 字符）。提取文本不含命中时（命中落在 id / 时间戳等
元数据上）该行不计入。

## 4. 前端契约

- `SearchHit.kind` 新增 `'chat-text'`；可选字段 `snippet?: string`、`matchCount?: number`。
- `SearchGroup.kind` 新增 `'chat-text'`（组标题 = t('对话内容')），排序在「会话」组之后、
  「工作区文件」组之前。
- 点击 / Enter 分派：`'chat-text'` 与 `'chat'` 同路——打开该会话。
- 行渲染：`chat-text` 行的第二行直接渲染完整命中片段（不复用 40 字符 hint 截断——
  片段在服务端已按 ±30 截好）。

## 5. 判据

| 层 | 判据 |
| --- | --- |
| server | `tests/sessionSearch.test.ts`：命中 / 大小写不敏感 / 每会话片段与计数封顶 / 扫描会话上限截断 / 查询越界判别拒绝 / 元数据命中不计 / 按类型提取 / fail-soft（checkpoint 合成 id 由 `sessionArchive.list` 的既有排除口径天然跳过） |
| web | `web/test/sessionSearch.test.ts`：chat-text 分组排序（matchCount 优先）/ 完整片段渲染 + 徽标 / 点击回环（openHit → onSelect） |
| parity | `search.all` 为既有 RPC（纯增量返回体）——parity 计数不变；`apiClientParity` 既有条目自动覆盖 |
| 全量 | `npm run web:test` 全绿 |

## 6. 风险与取舍

- **性能**：线性扫描 `.jsonl` 在百会话量级实测可接受（list 全扫 47.5ms 基线）；
  上限 200 会话 / 每文件逐行小写预筛保证最坏情况可控。超过 200 会话的工作区
  `truncated: true`——新会话（mtime 新者先扫）优先覆盖。
- **隐私**：内容搜索只在**本机磁盘**上做，无任何上行；与既有 `audit.query` 同一口径。
- **兼容**：`search.all` 返回体纯增量；`SearchHit.kind` 是联合类型扩展，
  `SearchResults` 行渲染按 kind 分支，旧消费者（若有）对未知 kind 走既有 else 分支不受影响。
