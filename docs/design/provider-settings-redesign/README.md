## 2. 设计目标与非目标

**目标**：
- 扫读优先：一屏看清 8 家厂商「谁在用、谁配好了、谁没配」，零输入框出现在总览层；
- 编辑聚焦：所有写操作（Key/检测/模型/启用）收进单一编辑面，动线 ≤ 2 步；
- 状态归一：**一个厂商同一时刻只有一个状态档**（● 当前 / ✓ 已配置 / ○ 未配置 / ! 检测失败）；
- 「当前」判定单一真源（`model.catalog` 的 `active.id`），修复 P3；
- 保持单色体系（状态=字形+明度，不引品牌色相）、antd v6、磨砂、圆角阶梯、ConsoleCard 语言。

**非目标**：不改服务端 RPC（catalog/probe/config.update/enableProvider 全复用）；
不改 providerPresets 数据结构（不加 icon 字段——首字徽标在前端生成）；
不动「默认模型与端点」卡（那是另一个 ConsoleCard）。

## 3. 方案 A（推荐）：厂商网格总览 + 编辑抽屉

```
┌──────────────────────────────────────────────────────────────────────┐
│ 模型与厂商                                     [服务端配置]           │
│                                                                      │
│ ┌──────────────────────────────────────────────────────────────────┐ │
│ │ 厂商接入                                    1/8 已配置   [刷新]  │ │
│ │ 保存 Key → 检测 → 启用。凭据由服务端打码存储，界面不回显原文。      │ │
│ │                                                                  │ │
│ │ ┌───────────────┐ ┌───────────────┐ ┌───────────────┐            │ │
│ │ │(DS) DeepSeek  │ │(MK) Moonshot  │ │(ZG) 智谱 GLM  │  …3 列网格 │ │
│ │ │ ● 当前使用    │ │ ○ 未配置      │ │ ○ 未配置      │            │ │
│ │ │ deepseek.com  │ │ 未实测        │ │ 免 Key?       │            │ │
│ │ └───────────────┘ └───────────────┘ └───────────────┘            │ │
│ │ ┌───────────────┐ ┌───────────────┐ ┌───────────────┐            │ │
│ │ │(OA) OpenAI    │ │(AN) Anthropic │ │(OL) Ollama    │            │ │
│ │ │ ○ 未配置      │ │ ○ 未配置      │ │ ○ 未配置      │            │ │
│ │ └───────────────┘ └───────────────┘ └───────────────┘            │ │
│ └──────────────────────────────────────────────────────────────────┘ │
│                                                                      │
│ ┌──────────────────────────────────────────────────────────────────┐ │
│ │ 默认模型与端点（现状不动）                                        │ │
│ └──────────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────┘

点任意厂商卡 → 右侧编辑抽屉（Drawer，~480px，Esc/遮罩关闭，焦点归还）：

┌──────────────────────────────────────┐
│ ✕  DeepSeek            ● 当前使用    │
│ https://api.deepseek.com             │
│──────────────────────────────────────│
│ API Key                              │
│ [已保存 sk-****5137，输入新值覆盖 ]   │
│ [保存 Key]  [检测]                   │
│                                      │
│ 可用模型（检测后出现）               │
│ [deepseek-chat            ▾]        │
│ [deepseek-reasoner        ▾]        │
│                                      │
│ [启用此厂商]   ← 检测成功后主按钮    │
│ ⚠ 检测未通过：…（错误时红色 Alert）  │
└──────────────────────────────────────┘
```

- 总览卡：首字徽标（单色墨芯片，Ω 同款语言）+ 名称 + **单**状态档 + 一行摘要
  （baseUrl 或状态说明，超长省略号）；当前厂商卡描边高亮。
- 抽屉内完成全部写操作；检测/保存互不阻塞（busy 态按钮 loading）。
- 优点：页面恒定高度（网格 ~3 行）、扫读最强、编辑聚焦；与 Drawer/PickerModal 语言一致。
- 代价：进编辑多一次点击；抽屉是本仓新形态（antd Drawer 已在 vendor）。

## 4. 方案 B：紧凑单列 + 单开手风琴

```
┌──────────────────────────────────────────────────────────────┐
│ 厂商接入                                   1/8 已配置 [刷新] │
│──────────────────────────────────────────────────────────────│
│ (DS) DeepSeek        ● 当前使用   sk-****5137   [编辑 ▾]    │
│   ┌─ 仅一行展开（点编辑，其余行自动收起）─────────────────┐  │
│   │ API Key [已保存 sk-****5137，输入新值覆盖  ]          │  │
│   │ [保存 Key] [检测]   可用模型 [deepseek-chat ▾]        │  │
│   │ [启用此厂商]                                          │  │
│   └──────────────────────────────────────────────────────┘  │
│ (MK) Moonshot Kimi   ○ 未配置              —           [编辑]│
│ (ZG) 智谱 GLM        ○ 未配置              —           [编辑]│
│ (OA) OpenAI          ○ 未配置              —           [编辑]│
│ …（8 行恒定高度）                                           │
└──────────────────────────────────────────────────────────────┘
```

- 行内摘要 = 打码 Key 或状态说明；「编辑」单开手风琴（一次只展开一行，根治 P4）。
- 优点：与现有 ConsoleCard 语言一致、改动最小、无新组件形态。
- 缺点：展开行仍纵向撑高；总览信息密度低于网格。

## 5. 需求问题（请逐条拍板）

**Q1（形态）**：选方案 A（网格 + 抽屉，推荐）还是 B（单列单开手风琴）？

**Q2（厂商徽标）**：默认用**首字徽标**（单色墨芯片，如「DS/MK/ZG」，不引入品牌色相，
守 colorSystem 纪律）。要品牌色块的话需要 theme.css 色板豁免（每家一个固定色），
并放松 §2.4「不靠色相区分」口径——不建议，默认不做。

**Q3（状态归一）**：统一成四档：● 当前使用 / ✓ 已配置（未实测或已实测）/ ○ 未配置 /
! 检测失败。检测成功时在**编辑面**内显示「可用 · N 个模型」，总览层不显示。
可以吗？

**Q4（「当前」判定修复）**：`isActiveProvider` 收敛为「`model.catalog` 的 `active.id`
=== preset.id」（单一真源），修掉三行同亮。会顺带修 `activePreset` 的同源逻辑
（baseUrl 精确匹配 > adapter 匹配，其余一律不算当前）。

**Q5（动线合并）**：编辑面里「保存 Key」与「检测」合并为「保存并检测」主按钮
（Key 无变更时按钮文案为「检测」）？还是保留两步分开？推荐合并（少一步，
状态机仍保三段：未配置→已保存→已实测）。

**Q6（折叠/展开默认）**：方案 A 下网格全部收起（无展开概念）；方案 B 下
「当前厂商默认展开、其余收起、单开」。沿用吗？
